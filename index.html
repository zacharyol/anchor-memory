anchor — agents that remember their own work

mm + ms: when an AI agent's context gets compacted, the summary loses the details — tool names, decisions, why-nots — and the agent rebuilds things it already built. anchor archives every raw session event before compaction, indexes the entities, and auto-detects "the agent sees p3c2 but doesn't know what it is" — then recovers the answer with citations. Two pieces nobody else ships: the auto-trigger (detect the gap for the agent) and the negative-result relay (failed searches pass their tried-log down the chain).

benchmark — vanilla compaction vs anchor (selective card)

Real data: the archive is the operator's actual OpenCode session history. Agent = llama3.1:8B on local Ollama, temperature 0.2. Fact coverage = fraction of ground-truth facts present in the answer. Recall = fraction of questions with coverage ≥ 50%.

Full methodology + per-version breakdown in the repo's DESIGN.md. Sampling wobble (same question, repeated) measured at ±5–6% — model randomness is small; question difficulty dominates. Trigger fire precision on labeled real data: 58% of fires were genuine gaps (firing is free; junk is filtered at the card layer).

the search ladder

write path (mm)

Every user message, assistant text and tool call lands in an append-only JSONL archive before compaction can destroy it. Entities are extracted at write time into an index: entity → where it's explained. Compaction also emits a manifest into the summary so cheap lookups stay cheap.

read path (ms) — rungs

rung 0 index + workspace filenames + file docstrings — free
rung 1 BM25 over raw records, session-scoped — free
rung 2 LLM rewording ("how would I have said it?") — ~1 call
rung 3 piece-by-piece reconstruction from creation-shaped neighbors
Misses return a tried-log — the negative result the relay passes on.

case study: ai.py — "found" is not "explained"

31 archive records mention ai.py; the first-mention evidence was a glob path-listing with zero facts. The resolver said FOUND and served a card that looked like memory and carried nothing — the negative-result problem wearing a success costume. Fix: best-explanation ranking (decisions + compaction summaries outrank listings) and file-type entities get their docstring read from disk. Card before: a path dump. Card after: """AI backends (bounded background workers) + HTML sanitizer for the village internet. — the file's own words.

set it up — 3 steps, ~2 minutes

1 · install

pip — that's the whole install:

pip install anchor-memory

from source instead:

pip install git+https://github.com/zacharyol/anchor-memory.git

no installer at all: copy the anchor/ folder — it is stdlib-only Python 3.11+, zero dependencies. Verify any of them:

python -m anchor.selftest   # all checks passed → you're good

2 · wire it into your tool

OpenCode — opencode.json:

{
  "mcp": { "servers": {
    "anchor": { "type": "local", "command": ["anchor-mcp"] } } }
}

Claude Code — .mcp.json:

{ "mcpServers": { "anchor": { "command": "anchor-mcp" } } }

pip-installed, anchor-mcp is on PATH. Folder-copy instead? Use ["python", "-m", "anchor.mcp_server"] with cwd set to the folder's parent.

Restart the session — your agent now has anchor_resolve, anchor_check, anchor_search, anchor_sessions, anchor_sync, anchor_relay, anchor_stats.

3 · feed it and use it

  1. anchor_sync — ingests your real session history from the local database (incremental; first run rebuilds, ~30s).
  2. anchor_check — paste any summary; it lists every name that's mentioned but unexplained.
  3. anchor_resolve("p3c2") — one card, one citation: what it is + where the file is.
  4. After any compaction, just ask your agent "what did I say about X?" — instead of guessing, it syncs → resolves → answers with citations.

Optional: a local Ollama unlocks ladder rung 2 (LLM rewording) — anchor finds it automatically at 127.0.0.1:11434.

teach your agent WHEN to use it — 30-second AGENTS.md block

The trigger auto-detects forgotten names, but the agent still decides whether to reach for memory. Paste this into your project's AGENTS.md (full version: AGENT_PROMPT.md in the repo):

## anchor memory rules
USE anchor when:
- recall questions ("what did I say / what was that tool / how does X work
  if we built it")  → anchor_sync, anchor_search, anchor_resolve
  → answer with the citation, never from a guess
- you see a name you can't explain → anchor_resolve it. never rebuild silently.
- before building anything that might already exist → resolve first (0.1 ms vs 30 min)
- right after a compaction → anchor_sync, anchor_check on the summary

DO NOT use anchor when:
- brand-new code (names that can't exist yet)
- general knowledge: language syntax, public docs — that's training data
- external/web lookups · brand-new project with no history

rule: anchor answers "what did WE make here" — the internet answers
"what does the world know". unsure if something exists? one resolve
costs ~0.1 ms — check, then build.
